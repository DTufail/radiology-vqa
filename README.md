# Grounded Multi-Agent Radiology VQA

A retrieval-augmented visual question answering system for radiology. Every answer the system produces is grounded in retrieved evidence from a structured biomedical knowledge base — not generated from model weights alone.

**Status:** Phase 2 of 4 complete. RAG retrieval pipeline is operational.

---

## Problem Statement

Medical VQA models are unreliable because they hallucinate clinical facts. This system addresses that by separating *what to say* (retrieval) from *how to say it* (generation). A question about a chest X-ray first retrieves factual context from a knowledge index built on the SLAKE medical KG, then passes that grounded context to a reasoning agent.

## System Architecture

```

│                      Offline (Build Time)                   │
│                                                             │
│  SLAKE KG ──► KGProcessor ──► Documents ──► Embedder ──►    │
│  (en_disease, en_organ,    (NL templates,   (S-PubMedBert)  │
│   en_organ_rel CSVs)        dual strategy)                  │
│                                                ▼            │
│                                           FAISSIndexer      │
│                                           data/indices/     │
└─────────────────────────────────────────────────────────────┘
                              │
                              │ load once at startup
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                      Online (Inference)                     │
│                                                             │
│  Image + Question                                           │
│       │                                                     │
│       ▼                                                     │
│  [Phase 3] Visual Grounding Agent                           │
│       │  structured findings                                │
│       ▼                                                     │
│  Retriever.retrieve(query, top_k=5)                         │
│       │  list[RetrievalResult]  ← text + citation + score   │
│       ▼                                                     │
│  [Phase 4] Answer Generation Agent                          │
│       │  grounded answer                                    │
│       ▼                                                     │
│  Final Answer + Evidence Citations                          │
└─────────────────────────────────────────────────────────────┘
```

## Setup

### 1. Install dependencies

```bash
python -m venv .venv
source .venv/bin/activate
make install
```

### 2. Configure environment

```bash
cp .env.example .env
# Edit .env if your data paths differ from the defaults
```

Default `.env.example`:
```
DATA_DIR=./data
SLAKE_DIR=./data/raw/Slake1.0
LOG_LEVEL=INFO
```

### 3. Download datasets

VQA-RAD and PathVQA download automatically from HuggingFace:

```bash
make download-data
```

SLAKE requires a manual download from the [SLAKE project page](https://www.med-vqa.com/slake/). Place the extracted directory at:

```
data/raw/Slake1.0/
├── imgs/
├── train.json
├── validate.json
├── test.json
└── KG/
    ├── en_disease.csv
    ├── en_organ.csv
    └── en_organ_rel.csv
```

### 4. Validate data

```bash
make validate-data
```

## Building the Knowledge Index

The FAISS index is built offline once and loaded at inference time.

```bash
make build-index-kg
```

This will:
1. Load 2,600 KG triples from the SLAKE KG CSVs
2. Convert them to 2,987 natural-language documents via NL templates and entity summaries
3. Embed all documents with `pritamdeka/S-PubMedBert-MS-MARCO` (~440MB, downloaded on first run)
4. Build a `IndexFlatIP` FAISS index and save to `data/indices/`

Expected output:
```
--- Index Summary ---
  kg_disease           2501 docs
  kg_organ              383 docs
  kg_organ_rel          103 docs
  TOTAL                2987 docs
  index.faiss size:    8.75 MB
  Build time:          ~300s
  Index saved to:      data/indices
```

### Validate retrieval quality

```bash
make test-retrieval
```

Runs 10 representative medical queries and prints ranked results with scores. Expected behaviour: scores span 0.88–0.99 with clear discrimination; top-1 result is semantically correct for all queries.

## Testing

```bash
make test        # Fast tests only — no model downloads, runs in <5s
make test-slow   # Full suite including embedding model and retrieval
```

| Tier | Count | What it covers |
|------|-------|----------------|
| Fast | 40 | Schema validation, chunker, KG processor, indexer/retriever (MockEmbedder) |
| Slow | 13 | Real embedding model: shapes, L2-norm, semantic ordering, end-to-end retrieval |

Fast tests use a `MockEmbedder` (8-dim, deterministic random vectors) injected via constructor. The `sentence-transformers` model is never imported in fast tests.

## Configuration

All settings live in `src/radiology_vqa/config.py` and can be overridden via environment variables or `.env`:

| Setting | Default | Description |
|---------|---------|-------------|
| `DATA_DIR` | `./data` | Root data directory |
| `SLAKE_DIR` | `./data/raw/Slake1.0` | Path to SLAKE dataset |
| `EMBEDDING_MODEL` | `pritamdeka/S-PubMedBert-MS-MARCO` | Sentence-transformers model |
| `INDEX_DIR` | `./data/indices` | FAISS index output directory |
| `CHUNK_SIZE` | `512` | Words per chunk (for future PubMed ingestion) |
| `CHUNK_OVERLAP` | `50` | Overlap words between chunks |
| `RETRIEVAL_TOP_K` | `5` | Default results returned per query |
| `RETRIEVAL_MIN_SCORE` | `0.3` | Minimum cosine similarity threshold |
| `LOG_LEVEL` | `INFO` | Python logging level |

## Embedding Model

**Model:** `pritamdeka/S-PubMedBert-MS-MARCO`

PubMedBERT fine-tuned on MS-MARCO passage retrieval via contrastive learning. Chosen over alternatives for two reasons:

- **Domain alignment** — pre-trained on PubMed; biomedical terminology ("pulmonary", "myocardial infarction") is correctly encoded
- **Retrieval geometry** — contrastive fine-tuning on MS-MARCO produces discriminative embeddings; score spread is 0.88–0.99, not the 0.956–0.981 compression seen with plain MLM mean pooling

The initial prototype used `microsoft/BiomedNLP-BiomedBERT-base-uncased-abstract-fulltext` (a masked language model) which produced effectively random rankings despite biomedical pre-training. A sentence similarity model is required, not just a domain-adapted LM.
